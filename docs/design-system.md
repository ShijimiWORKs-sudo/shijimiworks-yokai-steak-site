# ShijimiWORKs / 妖怪ステーキ Design System

## 1. サイト全体のデザイン方針

このサイトは、ひとりの制作者が持つ「仕事としての制作」と「作品としての創作」を、二つのブランドで見せるポートフォリオです。共通する品質は、読みやすさ、信頼感、触れる楽しさ、軽量な実装です。

- 情報設計を先に置き、装飾は意味を補強するために使う
- PCでは一枚絵のようなHero、スマホでは内容が自然に縦へ流れる構成にする
- Server Componentを基本とし、動きが必要な小部品だけClient Componentにする
- 外部リンク、CTA、準備中状態を見た目だけで区別できるようにする
- CSS、SVG、既存画像を優先し、重い動画や大量の画像を使わない

## 2. ShijimiWORKsのデザイン方針

キーワードは、AI制作スタジオ、白、アイスブルー、ネイビー、ガラスUI、AIダッシュボード、Web制作、自動化、記事制作、相談しやすさ、信頼感です。

目標は「何を頼めるかが一目でわかる、清潔で先進的なAI制作スタジオ」。役所的な均一さは避け、ワークフロー、ノード、制作ボード、軽い発光で“作っている場所”を感じさせます。

## 3. 妖怪ステーキのデザイン方針

キーワードは、夜の映画館、怪談、物語の入口、Podcast、原稿、映画チケット、マイク、音声波形、フィルム粒子、黒、深い茶、アンバー、金、余韻です。

目標は「夜に読む、観る、聴く物語へ入っていく、視覚的に面白い創作ポートフォリオ」。怖さを強調しすぎず、暗室の温かい光、紙、上映券、声の気配で“温かい怪しさ”を作ります。

## 4. 共通ホームのデザイン方針

左右分割、AIと物語、白と黒、光の境界線、一枚絵感、Two Names, One Studioを核にします。

目標は「ShijimiWORKsと妖怪ステーキの二面性が、最初の3秒で伝わる共通ホーム」。中央コピーは境界をつなぐ役割とし、左右のCTAは進む先が直感的に分かる大きさとコントラストを持たせます。

## 5. 色

| 用途 | 色 | 参考値 |
| --- | --- | --- |
| 共通背景 | Warm white | `#f7f7f5` |
| ShijimiWORKs主色 | Studio navy | `#0f2f49` |
| ShijimiWORKs差し色 | Ice blue | `#38bdf8` / `#e0f2fe` |
| 妖怪ステーキ背景 | Cinema black | `#080402` |
| 妖怪ステーキ補助 | Deep brown | `#211008` |
| 妖怪ステーキ差し色 | Amber / gold | `#d97706` / `#f5c875` |
| 本文 | Ink | `#0f172a` |
| 補助本文 | Slate | `#64748b` |

色は面積比を守ります。明色ページでは白を主役にし青は反応へ、暗色ページでは黒・茶を主役にしアンバーは光源へ使います。

## 6. 文字

- 日本語本文は現行のゴシック体系を維持する
- ShijimiWORKs見出しは太く、短く、機能的にする
- 妖怪ステーキ見出しは明朝・serifを使い、映画ポスターの余韻を持たせる
- 英字のeyebrowは小さく、太く、字間を広げる
- 本文はスマホでも16px相当と十分な行間を確保する
- 画像内文字に情報を依存させず、重要文言は必ずHTMLで持つ

## 7. 余白

- セクション上下：モバイル64px前後、PC80〜96px
- Hero内：情報の塊同士を32〜56px離す
- カード内：20〜28px
- CTA群：12px以上
- 余白は“高級感”と“読み順”のために使い、単に画面を広げない

## 8. カード

- 共通角丸：24px前後。Heroの大枠は32pxまで
- ShijimiWORKs：白〜淡い青、細い境界、柔らかい影、ガラス感
- 妖怪ステーキ：深い茶、アンバー境界、紙・上映券・ポスター感
- hoverは`translateY(-4px)`程度、境界色と影を連動させる
- 一覧カードは高さを揃え、CTAを最下部へ置く
- v1.3共通語彙：`.studio-glass-card`、`.youkai-ticket-card`、`.media-door-card`

## 9. CTA

- 最重要CTAは塗り、第二CTAはoutline
- タップ領域は最低44px、Hero CTAは48px以上
- ShijimiWORKsはブルーの発光、妖怪ステーキはアンバーの発光
- 外部リンクにはLucideの外部リンクアイコン、メールにはMailアイコンを使う
- hoverだけに意味を依存させず、文言で行き先を示す

## 10. アニメーション

- Framer Motionは`MotionSection`など小さなClient Component内だけで使う
- 初期表示・スクロール表示はopacityとY方向18px程度
- durationは500〜700ms、delayは必要最小限
- カードの常時浮遊はHeroの主要ビジュアルだけに限定する
- CSS hoverは200〜300msを基本にする
- `useReducedMotion`と`prefers-reduced-motion`の両方へ配慮する
- ページ全体をClient Component化しない

## 11. OGP画像をWebに反映する方針

OGP画像は完成見本と色・構図の参照元です。v1.3では画像をそのまま全面表示せず、CSSとHTML UIを主役にしたうえで補助的に使います。

- `common-ogp.png`：共通ホームHero背景・左右分割ビジュアルの参考に使う
- `shijimiworks-ogp.png`：ShijimiWORKs Hero右側ビジュアルに使う
- `youkai-steak-ogp.png`：妖怪ステーキ Hero背景または右側ビジュアルに使う
- 画像内文字とHTML文字が重複するため、overlay、opacity、position、cropで調整する
- 画像は`.ogp-hero-backdrop`内へ置き、HTML本文より下のレイヤーにする
- Next/Imageを使い、`sizes`と優先読み込みの範囲をHeroだけに限定する
- PCでは構図を見せ、スマホではopacityを下げるか一部をcropして控えめにする
- コントラスト不足時はブランド別overlayを追加し、画像そのものを加工しすぎない

## 12. やってはいけないこと

- OGPの文字入り画像だけでHeroを完成させる
- 全ページをClient Componentにする
- Framer Motionを全要素へ付ける
- 常時大きく動く背景、動画背景、強いパララックス
- 可読性を下げるノイズ、ぼかし、低コントラスト
- 青とアンバーを同じ面積・強さで混ぜる
- 既存ブランドリンク、metadata、ルーティングをデザイン都合で変更する
- UI部品を先回りして大量作成する
- 375pxで横スクロールを発生させる

## v1.3実装メモ

1. `VisualHeroFrame`を各Heroの右側または背景レイヤーへ段階的に導入する
2. OGP画像はNext/Imageで読み込み、`media`として渡す
3. 最初はHeroだけを対象にし、Works・Articlesへ画像を拡張しない
4. `MotionSection`はHero直下または主要セクション単位で使用する
5. 画像あり／なし、reduced motion、375px、1440pxを同じ変更内で確認する
